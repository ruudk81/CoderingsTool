# Step 5 Codebook Generator — Cache Logic

## Cache Type: Metadata Only

Step 5 produces **metadata only** (a single `CodingResultsCache` object). It does not produce a growing model — the codebook is a dataset-level structure, not per-respondent data.

Storage: SQLite-backed with pickle serialization. Filename pattern: `{prefix}_{step}_{datafile}_{variable_key}.pkl`

## Input Files

| Step name | Prefix | Model class | Type | Method | Source |
|-----------|--------|-------------|------|--------|--------|
| `"taxonomy"` | 005 | `TaxonomyResultsCache` | Metadata (single) | `load_metadata_from_cache()` | Step 4 — partition_set, per-domain facets/attributes/assignments |
| `"extracted_ideas"` | 004 | `ExtractionMetadata` | Metadata (single) | `load_metadata_from_cache()` | Step 3 — survey_question, language, dimension, specifiers |

Step 5 does **not** load the step 4 growing model (`taxonomy_classified`). It only needs the taxonomy structure (facets, attributes, assignment counts) from the metadata cache.

## Output Files

| Step name | Prefix | Model class | Type | Method | Contents |
|-----------|--------|-------------|------|--------|----------|
| `"mece_codes"` | 006 | `CodingResultsCache` | Metadata (single) | `save_metadata_to_cache()` | partition_set, partition_results, label_counts, total_categories, raw_codes |

### CodingResultsCache Contents

```python
CodingResultsCache:
    partition_set: DomainSet                          # Domain definitions (passed through from step 4)
    partition_results: Dict[str, DomainResultModel]   # Per-domain taxonomy results (passed through)
    label_counts: Dict[str, int]                      # Partition → unique label count
    label_source: str                                 # Label source config value
    total_categories: int                             # Total number of final codes
    raw_codes: List[Dict]                             # ConsolidatedCode.model_dump() dicts
```

The `raw_codes` field stores serialized `ConsolidatedCode` objects. Downstream consumers reconstruct them via `ConsolidatedCode(**d)`.

## Cache Key Scheme

```
Variable key: generated by generate_enhanced_variable_key(selected_variables, is_merged, sample_size)

Metadata file: 006_mece_codes_metadata_{datafile}_{variable_key}.pkl

SQLite key:   (filename, "mece_codes_metadata", variable_key)
```

## Cache-Hit Logic

```python
# Check metadata cache
if not force_recalc and cache_manager.is_cache_valid(filename, "mece_codes_metadata", variable_key):
    mece_cache = cache_manager.load_metadata_from_cache(filename, "mece_codes", variable_key, CodingResultsCache)
    if mece_cache:
        return  # Skip P8-P9
```

## Data Flow

```
Step 3 cache (prefix 004)
  └─ extracted_ideas_metadata          ──→ [Step 5 input: survey context, dimension]

Step 4 cache (prefix 005)
  └─ taxonomy_metadata                 ──→ [Step 5 input: facets, attributes, assignments per domain]
                                            │
                                    P8 per-domain code generation
                                    P9 cross-domain consolidation
                                            │
                                            ▼
Step 5 cache (prefix 006)
  └─ mece_codes_metadata               ──→ [Step 6 reads this: codebook (raw_codes) + taxonomy context]
```

## Downstream Consumers

- **Step 6** loads `CodingResultsCache` metadata — needs `raw_codes` (codebook) for assignment, plus `partition_set` and `partition_results` for domain context
