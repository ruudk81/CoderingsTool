# Step 5 — Cache Logic

## Cache Type: Metadata Only

Step 5 produces **metadata only** (a single `CodingResultsCache` object). It does
not produce a growing model — the codebook is a dataset-level structure, not
per-respondent data.

Storage: SQLite-backed with pickle serialization. Filename pattern: `{prefix}_{step}_{datafile}_{variable_key}.pkl`

## Input Files

| Step name | Prefix | Model class | Type | Method | Source |
|-----------|--------|-------------|------|--------|--------|
| `"taxonomy"` | 005 | `TaxonomyResultsCache` | Metadata (single) | `load_metadata_from_cache()` | Step 4 — partition_set, per-domain facets/attributes/assignments |
| `"extracted_ideas"` | 004 | `ExtractionMetadata` | Metadata (single) | `load_metadata_from_cache()` | Step 3 — survey_question, language, dimension, template_prefix |
| `"taxonomy_classified"` | 005 | `TaxonomyClassifiedModel` | Growing (List) | `load_from_cache()` | Step 4 — per-respondent ideas with attribute, valence, instance, interpretation |

`taxonomy_input.build_attribute_refs()` reads `partition_results[*].attributes`
directly (dict or Pydantic model, either shape) — it is the one place in step 5
that knows step 4's attribute dict shape, so a step-4 field rename is a
one-file fix. `build_idea_units()` is the equivalent for the growing model.

**Legacy read path — production refuses it, quarantine still honours it.** The
legacy `taxonomy_corrected` / `taxonomy_classified_corrected` keys come from the
old P9 over-merge corrector, which no longer exists; current step-4 runs never
write them, and step 4 invalidates stale ones right after every fresh taxonomy
save. The quarantined `_quarantine_v1/run_codeGenerator.py` still prefers those
keys over the plain ones when they are valid, keeping already-delivered work on
its shipped shape. `run_codebook.py` does **not** port that path and does
not silently ignore it either: it stops with an error when a valid
`taxonomy_corrected` cache exists, because building on a different taxonomy than
the one the cache advertises is worse than not building at all.

## Output Files

| Step name | Prefix | Model class | Type | Method | Contents |
|-----------|--------|-------------|------|--------|----------|
| `"mece_codes"` | 006 | `CodingResultsCache` | Metadata (single) | `save_metadata_to_cache()` | partition_set, partition_results, label_counts, total_categories, raw_codes. Written by `run_codebook.py` **or** `consensus/run_codebook.py` — same key, see "Eén cachesleutel, drie schrijvers" below; **not** written when `GeneratedCodebook.degeneration` is set — see Gotchas in `CLAUDE.md`. |

### CodingResultsCache Contents

```python
CodingResultsCache:
    partition_set: DomainSet                          # Domain definitions (passed through from step 4)
    partition_results: Dict[str, DomainResultModel]   # Per-domain taxonomy results (passed through)
    label_counts: Dict[str, int]                      # Partition → unique label count
    label_source: str                                 # Label source config value
    total_categories: int                             # Total number of final codes
    raw_codes: List[Dict]                             # ConsolidatedCode.model_dump() dicts
    codebook_narrative: str                            # legacy P8/P9 field — always "" from this chain
```

The `raw_codes` field stores serialized `ConsolidatedCode` objects. Downstream
consumers reconstruct them via `ConsolidatedCode(**d)`.

**No idea embeddings, cached or otherwise.** This chain never computes an
embedding — `synonym_of`/`umbrella_name` grouping (stage 2) and the MECE blind
probe (stage 5) both work on raw idea text and LLM judgment, not vectors. (The
old P8/P9 generator did embed every idea for representative-sample selection
and was removed 2026-08-13; nothing in the current chain replaced that need.)

## Cache Key Scheme

```
Variable key: generated by generate_enhanced_variable_key(selected_variables, is_merged, sample_size)

Metadata file: 006_mece_codes_metadata_{datafile}_{variable_key}.pkl

SQLite key:   (filename, "mece_codes_metadata", variable_key)
```

## Cache-Hit Logic

```python
# Check metadata cache (run_codebook)
if not force_recalc and cache_manager.is_metadata_cache_valid(filename, "mece_codes", variable_key):
    return None  # Skip generation entirely
```

`run_codebook()` defaults `force_recalc=False`, so a call on a valid cache
normally SKIPS regeneration — pass `force_recalc=True` to force a rerun. The
module's own `__main__` passes `force_recalc=True`, so a direct
`python -m pipeline.step_5_codeGenerator.run_codebook` always regenerates.
`run_pipeline.py` passes `force_recalc=step_force(5)`; `app_backend.run_step()`
defaults to `False`.

## Data Flow

```
Step 3 cache (prefix 004)
  └─ extracted_ideas_metadata          ──→ [language, primary_dimension]

Step 4 cache (prefix 005)
  ├─ taxonomy_metadata                 ──→ [attributes, assignments per domain]
  └─ taxonomy_classified (growing)     ──→ [literal answers per attribute card]
                                            │
                                    concept_inventory (respondent sets, no LLM)
                                    attribute_cards (no LLM)
                                    consolidation (1 LLM call)
                                    grouping (deterministic: partition, poles, degeneratie)
                                    codebook_writer (1 LLM call)
                                    three deterministic guards
                                    Overig sweep + verification (deterministic)
                                            │
                                            ▼
Step 5 cache (prefix 006)
  └─ mece_codes_metadata               ──→ [Step 6 reads this: codebook (raw_codes) + taxonomy context]
```

## Downstream Consumers

- **Step 6** loads `CodingResultsCache` metadata — needs `raw_codes` (codebook,
  reconstructed via `ConsolidatedCode(**d)`) for assignment, plus
  `partition_set` and `partition_results` for domain context. It computes its
  own embeddings independently; it never took anything embedding-related from
  this cache, before or after the rebuild.
- **Step 7** reads the same `raw_codes` (via `ConsolidatedCode`) for export,
  plus `ensure_assignment_ids(code_assigned_results, mece_cache, mece_cache.raw_codes)`.

## Eén cachesleutel, drie schrijvers

`mece_codes` is de enige step-5-uitvoersleutel. Tijdens het experiment dat de
huidige keten opleverde schreef die onder `mece_codes_v2`, zodat beide
codeboeken op dezelfde taxonomie naast elkaar te leggen waren; met de promotie van 2026-08-18 verviel die tweede
sleutel, en met hem het vergelijkingsgereedschap dat erop leunde.

Dat betekent ook: de v1-keten in `_quarantine_v1/` schrijft, als je hem draait,
onder diezelfde `mece_codes`. Twee ketens náást elkaar draaien kan niet meer
zonder een van de twee een eigen sleutel te geven — en sinds 2026-08-21 heeft
`consensus/run_codebook.py` diezelfde beperking, met opzet: hij schrijft
eveneens onder `mece_codes`, zodat step 6 en 7 zonder aanpassing op
consensus-codes kunnen draaien. De cache houdt dus op elk moment het codeboek
van de LAATST gedraaide keten — productie, v1 of consensus — en niet meer dan
dat ene.

**Niet geschreven bij degeneratie.** `run_codebook()` slaat de
`cache_mece_results`-aanroep over zodra `GeneratedCodebook.degeneration` is
gezet — een ontaard voorstel mag nooit landen waar step 6 het inleest. Het
codeboek en de scorecard worden nog wél geprint (melden, niet repareren); alleen
de schrijfactie vervalt. Een geblokkeerde run laat de vorige cache dus staan;
dat is bedoeld, geen mislukte save.

## Identity: minting at save + lazy migration

`cache_mece_results` runs `ensure_codebook_ids` before the save: every
`raw_codes` dict carries `code_id` (`K#`, minted in list order — written codes
then Overig) and `source_attribute_ids` (`A#`, resolved from `source_attributes`
names against the effective taxonomy structure). The structure dicts are
copies of the id-bearing taxonomy, so taxonomy `A#`s and codebook `A#`s share
one id space for NEW caches.

**Lazy migration** (the single documented exception to the no-legacy-tolerance
contract): pre-id codebooks are normalized IN MEMORY at load (`ensure_ids` hook
in `CacheManager.load_metadata_from_cache`); a legacy bare name that exists in
several domains resolves to ALL matching ids. Deterministic (frozen bytes →
same order → same ids); disk never mutated by normalization.
