# Step 4 — Cache Logic

> **P7.5 / P8 note:** Both the valence-neutral merge (P7.5) and cross-domain consolidation (P8) add **no** cache keys — each reloads, remaps, and overwrites the same `taxonomy` / `taxonomy_classified` keys in place (P7.5 after P7, then P8). No pre-merge snapshot is kept (unlike P7's `raw_*` fields).

## Two Types of Cached Data

Step 4 produces two cache outputs:

1. **Metadata** (single Pydantic object) — taxonomy structure used by step 5 for codebook generation
2. **Growing model** (List of Pydantic models) — per-respondent data with enriched facet/attribute fields, used by step 6

Both use SQLite-backed storage with pickle serialization. Filename pattern: `{prefix}_{step}_{datafile}_{variable_key}.pkl`

## Input Files (from Step 3)

| Step name | Prefix | Model class | Type | Method | Contents |
|-----------|--------|-------------|------|--------|----------|
| `"extracted_ideas"` | 004 | `IdeasExtractedModel` | Growing (List) | `load_from_cache()` | Per-respondent ideas with domain (L2), partial facet, abstraction ladder |
| `"extracted_ideas"` | 004 | `ExtractionMetadata` | Metadata (single) | `load_metadata_from_cache()` | primary_dimension, domains (each: key, label, definition, **boundary_test**, **exclusions**), lang, sector, entity, topic, perspective, intent, var_lab |

## Output Files

| Step name | Prefix | Model class | Type | Method | Contents |
|-----------|--------|-------------|------|--------|----------|
| `"taxonomy"` | 005 | `TaxonomyResultsCache` | Metadata (single) | `save_metadata_to_cache()` | partition_set (DomainDescription per domain, incl. boundary_test + exclusions), per-domain DomainResultModel (facets, facet_assignments, attributes, attribute_assignments, raw_attributes, raw_attribute_assignments, facet_valence, attribute_valence), label_counts, label_source |
| `"taxonomy_classified"` | 005 | `TaxonomyClassifiedModel` | Growing (List) | `save_to_cache()` | Per-respondent models with facet (L3), attribute (L4), partition_name, valence (resolved) populated |

## Cache Key Scheme

```
Variable key: generated by generate_enhanced_variable_key(selected_variables, is_merged, sample_size)
              e.g., "Q20_500" or "Q1_1+Q1_2_concat_semicolon_skip_full"

Metadata file: 005_taxonomy_metadata_{datafile}_{variable_key}.pkl
Growing model: 005_taxonomy_classified_{datafile}_{variable_key}.pkl

SQLite key:   (filename, step_name + "_metadata", variable_key)  — for metadata
              (filename, step_name, variable_key)                 — for growing model
```

## Cache-Hit Logic

```python
# Check metadata cache first
if not force_recalc and cache_manager.is_cache_valid(filename, "taxonomy_metadata", variable_key):
    taxonomy_cache = cache_manager.load_metadata_from_cache(filename, "taxonomy", variable_key, TaxonomyResultsCache)
    if taxonomy_cache:
        # Try loading growing model
        enriched = cache_manager.load_from_cache(filename, "taxonomy_classified", variable_key, TaxonomyClassifiedModel)
        if not enriched:
            # Backward compat: rebuild from metadata + step 3 data
            enriched = _build_taxonomy_enriched_models(encoded_text, taxonomy_cache)
            cache_manager.save_to_cache(enriched, filename, "taxonomy_classified", variable_key)
        return enriched
```

> **Current state:** `run_classifier.py` honors `force_recalc`. When `False` and both the `taxonomy` metadata and the `taxonomy_classified` growing model are valid (`is_metadata_cache_valid` + `is_cache_valid`), it skips P1-P8 entirely ("Taxonomy cache valid — skipping"). `run_pipeline.py` forces recalc only for the target step, so step 4 recomputes when it is the target and otherwise loads from cache.

## Growing Model Assembly

The growing model is **not** assembled incrementally during P1-P7. Instead, it is built once after all taxonomy processing completes, by `_build_taxonomy_enriched_models()`:

1. Build global lookups from `TaxonomyResultsCache.partition_results`:
   - `facet_lookup`: {idea_id → facet_name} (from all domains' `facet_assignments`)
   - `attr_lookup`: {idea_id → attribute_name} (from all domains' `attribute_assignments`)
   - `partition_lookup`: {idea_id → partition_name} (from domain membership)
   - `facet_val_lookup`: {idea_id → valence} (from all domains' `facet_valence`)
   - `attr_val_lookup`: {idea_id → valence} (from all domains' `attribute_valence`)

2. Iterate step 3 ideas (`List[IdeasExtractedModel]`):
   - For each idea: create `TaxonomyClassifiedSubmodel` with facet, attribute, partition_name, valence populated from lookups
   - **`domain` is canonicalized to `partition_name`** here (`idea.domain = idea.partition_name`). Step 3's `domain` label is Title Case while `partition_name` is lowercase; setting them equal at build time prevents casing drift so the two fields never diverge.
   - Valence cascade: P6 valence (most precise) > P3 valence > step 3 valence (inherited)
   - Wrap in `TaxonomyClassifiedModel` preserving response structure

3. Save as `List[TaxonomyClassifiedModel]` to `"taxonomy_classified"` cache

> **Raw P6 data**: The metadata cache also contains `raw_attributes` and `raw_attribute_assignments` per domain — the pre-P7 attribute state before cross-facet consolidation remaps. The growing model only carries post-P7 (consolidated) attributes. View scripts that need pre-consolidation data must read from the metadata cache.

> **P7.5 overwrite**: Between P7 and P8, the valence-neutral merge reloads the cached taxonomy + growing model, merges within-facet attribute pairs that differ only in valence into one descriptive attribute, and overwrites the same keys. Valence/confidence are preserved (they now carry the +/-).

> **P8 overwrite**: After P1-P7 build and cache the growing model above, P8 reloads it, remaps attributes/facets across domain boundaries (merge map keyed by `(domain, attribute_name)`), and overwrites the same `taxonomy` / `taxonomy_classified` keys. On a cross-domain move P8 updates both `partition_name` **and** `domain` on the idea, and carries its valence/confidence. No pre-P8 snapshot is kept.

## Data Flow

```
Step 3 cache (prefix 004)
  ├─ extracted_ideas (growing)         ──→ [Step 4 input: ideas to classify]
  └─ extracted_ideas_metadata          ──→ [Step 4 input: dimension, domains, survey context]
                                            │
                                taxonomy pipeline (6 phases, incl. P8 cross-domain)
                                            │
                                            ▼
Step 4 cache (prefix 005)
  ├─ taxonomy_metadata                 ──→ [Step 5 reads this: facets, attributes, assignments per domain]
  └─ taxonomy_classified (growing)     ──→ [Step 6 reads this: enriched per-idea facet/attribute/partition]
```

## Downstream Consumers

- **Step 5** loads `TaxonomyResultsCache` metadata — needs facets, attributes, assignment counts for codebook generation
- **Step 6** loads `List[TaxonomyClassifiedModel]` growing model — needs pre-enriched ideas with facet/attribute/partition_name
