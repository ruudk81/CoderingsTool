# Step 3 Idea Extractor — Cache Logic

## Two Types of Cached Data

Step 3 produces two cache outputs:

1. **Growing model** (List of Pydantic models) — per-respondent data with extracted ideas, used by steps 4 and 6
2. **Metadata** (single Pydantic object) — dataset-level extraction context (dimension, domains, specifiers), used by steps 4, 5, and 6

Both use SQLite-backed storage with pickle serialization. Filename pattern: `{prefix}_{step}_{datafile}_{variable_key}.pkl`

## Input Files (from Step 2)

| Step name | Prefix | Model class | Type | Method | Contents |
|-----------|--------|-------------|------|--------|----------|
| `"quality_filter"` | 003 | `QualityFilteredModel` | Growing (List) | `load_from_cache()` | Per-respondent cleaned text with quality_filter flags |

Step 3 filters the input to meaningful responses only (`quality_filter=False`) before processing.

## Output Files

| Step name | Prefix | Model class | Type | Method | Contents |
|-----------|--------|-------------|------|--------|----------|
| `"extracted_ideas"` | 004 | `IdeasExtractedModel` | Growing (List) | `save_to_cache()` | Per-respondent ideas with domain, abstraction ladder, valence |
| `"extracted_ideas"` | 004 | `ExtractionMetadata` | Metadata (single) | `save_metadata_to_cache()` | primary_dimension, domains, lang, sector, entity, topic, perspective, intent, var_lab |

## Cache Key Scheme

```
Variable key: generated by generate_enhanced_variable_key(selected_variables, is_merged, sample_size)
              e.g., "Q20_500" or "Q1_1+Q1_2_concat_semicolon_skip_full"

Growing model file: 004_extracted_ideas_{datafile}_{variable_key}.pkl
Metadata file:      004_extracted_ideas_metadata_{datafile}_{variable_key}.pkl

SQLite key:   (filename, "extracted_ideas", variable_key)             — for growing model
              (filename, "extracted_ideas_metadata", variable_key)    — for metadata
```

## Cache-Hit Logic

```python
# In run_experiment.py, force_recalc is True by default (development mode)
# In pipeline.py, cache is checked before running:
if not force_recalc and cache_manager.is_cache_valid(filename, "extracted_ideas", variable_key):
    encoded_text = cache_manager.load_from_cache(filename, "extracted_ideas", variable_key, IdeasExtractedModel)
    extraction_metadata = cache_manager.load_metadata_from_cache(filename, "extracted_ideas", variable_key, ExtractionMetadata)
    if encoded_text and extraction_metadata:
        return encoded_text, extraction_metadata
```

## Growing Model Assembly

The growing model is assembled in `IdeaExtractor.extract()` after all phases complete:

1. **Phase 1-3**: discover context specifiers, primary dimension, and domains (dataset-level)
2. **Phase 4**: bootstrap measurement (probe calls for latency/token calibration)
3. **Phase 5**: per-response extraction via async queue + workers:
   - Each response → `DimensionExtractionModel` (list of ideas)
   - Per idea: `idea`, `instance`, `interpretation`, `abstraction`, `domain`, `facet` (hint), `valence`
   - Validation + retry (up to 2x) or fallback `PROCESSING_ERROR`
4. **Phase 6**: assemble `IdeasExtractedModel` per response:
   - Create `IdeasExtractedSubmodel` for each extracted idea
   - Generate `idea_id` as `{respondent_id}_{sequence_number}`
   - Set `template_prefix` from dimension canonical phrasing
   - Wrap in `IdeasExtractedModel` preserving response fields

## Metadata Assembly

`ExtractionMetadata` is built via `extractor.build_extraction_metadata()` after extraction:

```python
ExtractionMetadata(
    filename=filename,
    var_name=var_name,
    var_lab=var_lab,
    template_prefix=template_prefix,
    lang=lang, sector=sector, topic=topic,
    perspective=perspective, entity=entity, intent=intent,
    primary_dimension=primary_dimension,
    primary_dimension_description=primary_dimension_description,
    decision_tree_stop_position=decision_tree_stop_position,
    domains=[{key, label, definition}, ...]
)
```

## Data Flow

```
Step 2 cache (prefix 003)
  └─ quality_filter (growing)          ──→ [Step 3 input: filter to meaningful responses]
                                            │
                                   IdeaExtractor.extract()
                                   (6-phase pipeline: specifiers → dimension → domains → extraction)
                                            │
                                            ▼
Step 3 cache (prefix 004)
  ├─ extracted_ideas (growing)         ──→ [Step 4 reads this: ideas with domain + abstraction ladder]
  │                                    ──→ [Step 6 reads this: fallback if step 4 cache missing]
  └─ extracted_ideas_metadata          ──→ [Step 4 reads this: dimension, domains for taxonomy classification]
                                       ──→ [Step 5 reads this: survey context for codebook generation]
                                       ──→ [Step 6 reads this: survey context for code assignment]
```

## Downstream Consumers

- **Step 4** loads both:
  - `List[IdeasExtractedModel]` growing model — ideas to classify into facets and attributes
  - `ExtractionMetadata` metadata — primary_dimension (for `DimensionDefinition` lookup), domains (for partitioning)
- **Step 5** loads `ExtractionMetadata` metadata — survey_question, language, dimension, specifiers for codebook prompts
- **Step 6** loads:
  - `List[IdeasExtractedModel]` growing model — fallback ideas if step 4 cache is missing
  - `ExtractionMetadata` metadata — survey context for assignment prompts
- **Step 7** (export) may load growing model for complete response chain
